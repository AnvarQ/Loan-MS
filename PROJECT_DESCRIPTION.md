# Описание проекта: Loan Management System

## Информация о проекте

**Название проекта:** OST - Loan Management System
**Курс:** Основы современных технологий (OST)
**Тип проекта:** MVP (Minimum Viable Product)
**Статус:** Production Ready
**Дата создания:** 2025
**Версия:** 1.0.0

---

## Краткое описание

Loan Management System (Система управления кредитами) — это полнофункциональное веб-приложение для автоматизации процесса выдачи и управления кредитами. Система реализует современный подход к разработке с использованием RESTful API архитектуры, обеспечивая разделение бизнес-логики и пользовательского интерфейса.

Проект демонстрирует практическое применение современных технологий веб-разработки, включая Django REST Framework, JWT аутентификацию, контейнеризацию с помощью Docker и работу с реляционными базами данных.

## Ролевая модель

Система реализует трехуровневую ролевую модель доступа:

### 1. Customer (Клиент)

**Описание:** Конечный пользователь, получатель кредита

**Права доступа:**
- ✅ Просмотр собственных кредитных заявок
- ✅ Фильтрация своих кредитов по статусу
- ❌ Создание кредитных заявок (создает агент)
- ❌ Доступ к данным других клиентов

**Статус регистрации:** Автоматически активируется при регистрации

### 2. Agent (Агент)

**Описание:** Сотрудник, работающий с клиентами и создающий заявки на кредиты

**Права доступа:**
- ✅ Создание кредитных заявок для клиентов
- ✅ Редактирование неодобренных кредитов
- ✅ Просмотр всех кредитных заявок
- ✅ Просмотр списка клиентов
- ❌ Одобрение/отклонение кредитов
- ❌ Управление агентами

**Статус регистрации:** Требует одобрения администратором перед началом работы

### 3. Admin (Администратор)

**Описание:** Администратор системы с полным доступом

**Права доступа:**
- ✅ Полный доступ к административной панели Django
- ✅ Одобрение/отклонение кредитных заявок
- ✅ Одобрение/удаление агентов
- ✅ Создание других администраторов
- ✅ Просмотр и управление всеми пользователями
- ✅ Доступ к истории изменений
- ✅ Управление всеми данными системы

**Статус регистрации:** Создается через специальный эндпоинт или командную строку

## Функциональные возможности

### Управление пользователями

#### Регистрация и аутентификация
- Регистрация новых пользователей (Customer или Agent)
- Аутентификация с использованием email и пароля
- Генерация JWT токенов со сроком действия 2 часа
- Автоматическое хеширование паролей (PBKDF2 + SHA256)

#### Управление профилем
- Просмотр информации о текущем пользователе
- Получение данных профиля через API

#### Административные функции
- Просмотр списка всех пользователей (только Admin)
- Одобрение агентов для работы в системе
- Удаление пользователей
- Создание дополнительных администраторов

### Управление кредитами

#### Создание кредитных заявок
- Агент создает заявку от имени клиента
- Указание суммы кредита и условий
- Автоматическое связывание с клиентом и агентом
- Начальный статус: "NEW"

#### Обработка кредитных заявок
- Просмотр всех заявок (Admin/Agent)
- Одобрение заявки администратором (статус → "APPROVED")
- Отклонение заявки администратором (статус → "REJECTED")
- Редактирование неодобренных заявок агентом

#### Просмотр и фильтрация
- Просмотр всех кредитов (Admin/Agent)
- Просмотр собственных кредитов (Customer)
- Фильтрация по статусу:
  - `?status=NEW` — новые заявки
  - `?status=APPROVED` — одобренные кредиты
  - `?status=REJECTED` — отклоненные заявки

#### Аудит и история
- Автоматическое логирование всех изменений
- Сохранение истории статусов
- Возможность отката изменений
- Отслеживание автора изменений

## Модели данных

### User Model

```python
class User(AbstractUser):
    username = None  # Не используется
    email = EmailField(unique=True)  # Основной идентификатор
    is_customer = BooleanField(default=True)
    is_agent = BooleanField(default=False)
    is_admin = BooleanField(default=False)
    is_approved = BooleanField(default=True)

    USERNAME_FIELD = 'email'
```

**Поля:**
- `email` — уникальный email адрес (используется для входа)
- `is_customer` — флаг роли клиента
- `is_agent` — флаг роли агента
- `is_admin` — флаг роли администратора
- `is_approved` — одобрен ли агент для работы

### Loan Model

```python
class Loan(Model):
    customer = ForeignKey(User, on_delete=CASCADE)
    agent = ForeignKey(User, on_delete=CASCADE)
    amount = DecimalField(max_digits=12, decimal_places=2)
    loan_type = CharField(max_length=50)
    status = CharField(max_length=20, default='NEW')
    created_at = DateTimeField(auto_now_add=True)
    updated_at = DateTimeField(auto_now=True)
```

**Поля:**
- `customer` — клиент, получающий кредит
- `agent` — агент, создавший заявку
- `amount` — сумма кредита
- `loan_type` — тип кредита (личный, ипотека и т.д.)
- `status` — статус (NEW/APPROVED/REJECTED)
- `created_at` — дата создания
- `updated_at` — дата последнего изменения

**Статусы кредита:**
- `NEW` — новая заявка, ожидает рассмотрения
- `APPROVED` — одобрена администратором
- `REJECTED` — отклонена администратором

## Безопасность

### Аутентификация и авторизация

1. **JWT Токены**
   - Выдаются при успешной аутентификации
   - Срок действия: 2 часа
   - Передаются в заголовке: `Authorization: Bearer <token>`
   - После истечения требуется повторный вход

2. **Хеширование паролей**
   - Алгоритм: PBKDF2 с SHA256
   - Пароли никогда не хранятся в открытом виде
   - Используется salt для дополнительной защиты

3. **Permission-based Access Control**
   - Каждый endpoint защищен проверкой прав доступа
   - Кастомные классы permissions для каждой роли
   - Автоматическая проверка перед выполнением запроса

### Защита данных

1. **CORS Configuration**
   - Настроен django-cors-headers
   - Контроль доступа с разных доменов
   - Защита от CSRF атак

2. **Валидация данных**
   - Автоматическая валидация через Django REST serializers
   - Проверка типов данных
   - Защита от SQL инъекций через ORM

3. **Аудит изменений**
   - django-simple-history логирует все изменения
   - Сохранение истории для отката
   - Отслеживание автора каждого изменения

## Демонстрация функционала

### Сценарий 1: Регистрация и одобрение агента

1. Агент регистрируется через `/api/user/signup/` с флагом `is_agent: true`
2. Администратор видит нового агента в `/api/user/list-approvals/`
3. Администратор одобряет агента через `/api/user/approve-delete/<id>/`
4. Агент может войти и начать работу

### Сценарий 2: Создание и одобрение кредита

1. Агент создает кредит для клиента через `/api/loan/customer-loan/`
2. Кредит получает статус "NEW"
3. Администратор видит новый кредит в `/api/loan/list-loans-admin-agent/?status=NEW`
4. Администратор одобряет через `/api/loan/approve-reject-loan/<id>/`
5. Статус меняется на "APPROVED"
6. Клиент видит одобренный кредит в своем списке

### Сценарий 3: Редактирование кредита

1. Агент создает кредит с ошибкой в сумме
2. Агент исправляет через `/api/loan/edit-loan/<id>/`
3. Система сохраняет историю изменений
4. После одобрения редактирование запрещено

## Заключение

Loan Management System представляет собой полнофункциональное веб-приложение, демонстрирующее современные подходы к разработке backend систем. Проект реализует важные концепции:

- **RESTful API** — стандартный подход к построению веб-сервисов
- **JWT аутентификация** — современный метод безопасной аутентификации
- **RBAC** — ролевая модель управления доступом
- **Docker** — контейнеризация для упрощения развертывания
- **ORM** — объектно-реляционное отображение для работы с БД

Система готова к использованию как в качестве учебного проекта, так и в качестве основы для реального коммерческого продукта с дальнейшим развитием и масштабированием.
